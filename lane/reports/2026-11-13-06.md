## Client behavior and fixes

- `src/ai-proxy.js` configures only the fixed public `ai-proxy` URL on the
  shipped Pages origin. Only Boycott/Docent Silver answers are eligible. Local
  previews, `?ai=local`, other helpers and other Places stay simulated without a
  session request. The session bearer stays in memory; only the anonymous holder
  handle persists when storage works.
- The full client/server test exposed two dormant transport defects: local
  `show.agent` did not match server `show.agents`, and sending every visible
  article block exceeded the existing 6,000-token input envelope. The transport
  now maps the field and selects up to six question-relevant authored IDs from
  the already-visible blocks, including the appropriate child variant. It never
  sends block bodies, profile identity or hidden blocks, and no cap was raised.
- `src/ai.js` validates live proposal shape, cited visible IDs and exact local
  excerpts (or the fixed honest abstention). Failure returns validated simulation.
  Quota cooldown retains its limit reason, and cancellation during session
  bootstrap never starts a paid request.
- `src/staff.js` rechecks profile, Lens, visible context and helper grant before
  recording an offer, preserving the provider/fallback reason and server receipt
  ID. A stale or cancelled reply creates neither an offer nor a fake local failure
  receipt. An already-dispatched server call can still settle normally.
- `src/staff-ui.js` shares the same behavior in Page and 3D. Labels are **Live ·
  grounded answer**, **Simulated · live helper unavailable**, **Simulated · live
  limit reached**, or **Simulated · local helper**. Model names never determine
  those labels. The answer's sample/verification reason remains visible. Closing,
  navigating or reopening cancels a pending UI request; a changed Lens prompts a
  fresh question. A scoped color fix makes the Page helper sheet readable.
