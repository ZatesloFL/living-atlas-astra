## Kit data contract v1

A projection describes where authored Places and Things appear and which Paths and helpers are present. It resolves the same records in 3D, Page, and visitor preview. Drafts carry proposed edits alongside the projection. The version here identifies the data format. A revision identifies one published arrangement.

```text
Draft       { id, holderId, expiresAt, basedOn: RevisionId | null,
              projection, changes: RecordChange[] }
Projection  { schemaVersion: 1, rootPlaceId, rooms: Room[] }
Revision    { id, basedOn: RevisionId | null, projection,
              ownedRecordVersions: { ref, versionId }[], receiptId }
Room        { placeId, parentPlaceId: PlaceId | null, layout,
              pathIds: PathId[], pieces: Piece[], behaviors: Behavior[] }
Piece       { id, kind, ref, transform: { position: [x, y, z], yaw, scale },
              settings, behaviors: Behavior[] }
ref         { placeId } | { placeId, thingId } | { actorId }
RecordChange { op: create | update, kind: Place | Thing | Path | helper,
               ref: ref | { pathId }, fields, provenanceRef: ReceiptId | null }
```

- **Identity and layout.** `placeId` is the stable authored ID. `thingId` is scoped to its origin Place, and `actorId` identifies an existing actor or a proposed local attachment. A Path uses its stable ID and one of seamless, door, window, or embedded, with its canonical endpoints and consent. The room tree represents authored containment, while the Path graph governs crossing. Each non-root room has one parent in the tree, cycles are invalid, and nesting can extend to any depth. A piece ID is unique within its room and identifies a placement that can move independently of its target. Positions are room-local metres, yaw is radians, and scale is a positive factor within the registered kind’s limits. `layout` retains the existing kind, scene, slot, approach, scale, facing, and Outside/Door/Inside arrivals. An interior supplies a local coordinate frame, with its frontage and door in the parent scene.
- **Authored records.** The existing Place fields still hold author, visibility, consent settings, style, presentation, scores, blocks, audience versions, layers, and source references. Things retain the A6 block shape where applicable, including fallback representations and optional source pointer and load state. Shells read the Place they render, exhibits and fixtures read their Thing, and helper pieces read their Place-bounded actor. New Places, Things, and helpers can carry `backing_ref: null` or a verified Second Look reference supplied by its source. The Atlas never issues one. Record changes are typed and allowlisted. Builders can propose their declarations, while measured scores, ownership, standing, and grants come from their existing authorities.
- **Scores and references.** Place and Thing declarations and measurements use the six existing integer dimensions, 0–3. The crossing engine checks the exact nested subject and its enclosing gates, applies the higher of declared and measured, and owns threshold, filtered-admission, hard-limit, and revocation decisions. A foreign Place is a destination on a checked Path. A foreign Thing placement contains only its origin Place ID and Thing ID, plus local placement settings. Each resolves against live origin records and consent at use, including the origin's style controls. The host gains no edit rights. Public visibility alone confers no inclusion permission. If access is withdrawn or resolution fails, the engine may show only the placeholder the visitor is allowed to see. An owner editing their own unfiltered draft still has to pass the origin gates on a foreign reference.
- **Kit and behavior.** The kit registry owns setting schemas, accessibility requirements, transform limits, and cost. Room and piece rules use `{ when, if, then, target }` with allowlisted events, conditions, actions, and typed operands. For example, the existing screen record uses `{ when: "leave", if: "canView", then: "pause", target: "self" }`. A seat event may show that seat’s caption. Later entries from the brief use the same structure. Targets stay in the current Place. The runtime checks scope and current grants before actions, including a door action, and receipts governed outcomes. A look-only Docent uses the existing standing grant rule, with revocation. Suggest-or-higher helpers use leased grants and owner approval. Adding a piece to a draft gives the helper no live grant.
- **Publish and reset.** Place, tune, and scripted talk produce the same typed changes. Talk uses `ai.request` with a local simulated proposal schema, model and actor provenance, and an explicit keep or undo decision. Preview runs the same read-only Lens and pre-flight checks as Visit and issues no real visits or grants. Publish requires explicit owner approval, rechecks the base revision and current grants, scores, crossings, and budgets, and commits the new revision and its Receipt together. A retry for the same publish must yield the same outcome and Receipt. Drafts and proposals have expiry. Durable authored data and capabilities have their own lifecycles, independent of the layout. A revision retains the exact versions of its owned authored records, while foreign references always resolve live. Restore or private reset switches the projection through a new receipted revision. Previously published versions, Things, sources, grants, standing, and helper connections remain resolvable under their own rules. If other people rely on a Place, their use must be resolved before withdrawing the affected projection.
- **Performance budget.** Registry costs include instances, atlas tiles, live textures, behavior count, and projected draw cost. Publish checks each room’s enabled pieces, shell, and render overhead against engine-owned limits, including the existing full-quality scene ceiling of 22 draw calls. The check accounts for any nested content visible together. A portal to a separately rendered room pays its local cost, then the destination has its own budget. A referenced Thing uses a bounded kit presentation and counts toward the host’s budget. Any overage names the room and the costs blocking publish. Existing G3 per-kind caps remain in force. The precise room limits for new costs need calibration with the renderer before the budget implementation lands.

## First test — Arrival starter Place

An illustrative draft claims `sample-home` and gives it two authored children, `sample-home/drive` and `sample-home/workshop`. Both children are entered through ordinary Paths with arrivals. The labels below identify the content of the records staged by `changes` and the placements in `projection`.

| File 24 case | V1 representation |
|---|---|
| Interview and local-area choice | Private interview references feed the starter proposal. Only confirmed facts become Things the member chooses to author. Unanswered fields remain unset and locality has no placement unless opted in. |
| Light furnishing and supplied sources | One text Thing about a declared hobby may be proposed from model knowledge, with proposal provenance and owner confirmation. A supplied source is a separately cited Thing with an A6 source pointer and an honest load state. |
| Drive and workshop | Drive is a private archive shell, with source placeholders until connected. Workshop is a shell with a static Second Look link and explanation, null backing until connected, and no simulated Second Look actors. |
| Helper attachment | An optional look-only Docent on the home Place is a helper record plus a piece referring to its `actorId`. The owner issues its standing grant in the existing access system when the attachment is approved. |
| Shared Place and Thing | A checked Path points at the public civic table Place `studio/civic`. A Thing placement can resolve `{ placeId: "studio/civic", thingId: "lead" }` if the origin author’s current policy permits it. Neither case moves any origin record into the draft. |
| Three starts | Starter uses light furnishing and accepted selections. Scratch contains the claimed root and the two standard rooms with no optional furnishings. A template starts from the same projection shape with authored defaults and the same two standard rooms. Each can be edited as a draft. |

```json
    "settings": {}, "behaviors": []

  "changes": [{
    "op": "create", "kind": "Path", "ref": { "pathId": "home-civic" },
    "fields": { "from": "sample-home", "to": "studio/civic", "type": "door" },
    "provenanceRef": null
  }]

```

The same fields describe the existing hall. `ROOMS.boycott.id` is `tallahassee/1956`. Its `layout.interior` describes an interior of that same Place, with `city-boycott` as its entry Path, the existing spatial door projection, and the current arrivals, partitions, and bays. Each bay supplies the placed transform for its matching G3 block. The block’s `exhibit.kind`, settings and behaviors supply the registered screen, photo wall, listening station, newspaper, or seat-map piece. Its original scores, sample label, source pointer, and audience placement stay with the block. Use registry keys such as `boycott` at existing API boundaries and resolve them to authored IDs for the contract. The boycott’s existing Docent and grant are referenced by their current IDs.
