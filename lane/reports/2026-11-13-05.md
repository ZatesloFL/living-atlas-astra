## Root cause and its evidence limit

The live receipt proves the response failed the content-envelope gate; the raw
body was deliberately not retained, so its exact block subtype is unobserved.
The previous adapter required every Anthropic content block to be text. That
rejects a documented Haiku 5.5 default response: an empty `thinking` block with
an opaque signature followed by answer text.

Official documentation checked on 2026-11-13:
[thinking behavior](https://platform.claude.com/docs/en/build-with-claude/thinking),
[Messages content and usage types](https://platform.claude.com/docs/en/api/http/messages),
and the [Messages response example](https://platform.claude.com/docs/en/api/messages/create).
Haiku defaults to thinking with display omitted; thinking still contributes to
total output usage and the output limit. The optional reported breakdown is
`usage.output_tokens_details.thinking_tokens`.

`tests/fixtures/docent-haiku-thinking-response.json` is a constructed fixture,
not a recovered live response: public lead-block text, an empty thinking string,
a synthetic signature and synthetic usage of 600 input / 300 output tokens,
including 204 thinking tokens. Before the fix it returned
`provider_content_invalid` with no answer. After the fix the full mocked handler
accepts the exact lead excerpt and records 1,200 micro-USD at the test rates
(600 input + 300 × 2 output). Thinking is neither subtracted nor charged twice.
This demonstrates the compatibility defect, not a completed live retest.
