## Calling the entry point

```js
import { registerProjection } from './build-projection.js';

const {rootKey, roomKeys, arrival} = registerProjection(
  {projection, changes},
  {ownerId: activeProfile.id},
);
```

- Pass the initial, approved `Projection` and its authored `create` changes for Places, Things, Paths and optional helper records. A room’s `pathIds` lists its outgoing Paths. Each child needs a Path from its parent. Omitting `layout.scene` puts the rooms in the root’s own scene. Use distinct layout slots and Path positions for the Drive room and workshop. Supply scene-local `zone` bounds when physical crossings should update the current room.
- Use the claim’s actual profile ID for `ownerId`. Every registered Place carries it at `ROOMS[key].ownerId` and keeps its canonical `parentPlaceId`. The private default is hidden. Arrival supplies the owner from the approved claim, before constructing the World or opening the Page. The shared access and crossing code decides what the active profile may see and enter.
- `roomKeys` maps canonical authored IDs to runtime keys. New Places use their authored IDs as keys. A Path to an existing Place resolves its existing key and retains the canonical target in `edge.reference.placeId`. A public Thing selection stays in `room.kitPieces` as `{placeId, thingId}`. The publisher’s Thing stays in its origin Place. Authored Things carry their source and proposal receipt references.
- The return value’s `arrival` is the same inside-arrival shape used by travel. Use it with Arrival’s normal landing flow. A repeated registration of identical approved data is idempotent. Save the approved data with the local claim and replay it on reload. The registrar validates the batch before it mutates either catalog. A collision or invalid reference leaves both catalogs intact.
- Registration is the catalog step for an initial projection. Revision replacement, the publish transaction and its receipt, and automatic local persistence belong to the later publish lifecycle. Registering helper records preserves the attachment data for Staff’s scoped grant workflow.
