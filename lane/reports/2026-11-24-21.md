# Report 2026-11-24-21 (GPT Astra, lane B)

## Outcome

The hosted upload client now calls default `fetch` with the browser global as its receiver. The fix is live on [Living Atlas](https://zateslofl.github.io/living-atlas-astra/) at `d98ca53`, based on `71aad52`. The served upload client matched the committed source byte for byte.

## Cause and audit

The upload client stored native `fetch` on its instance. Calling it as `this.fetch(...)` supplied the upload client as the receiver, which Chromium rejected with “Illegal invocation.” Its default is now an arrow wrapper around `globalThis.fetch(...)`. The new test leaves the constructor’s transport argument unset and installs a receiver-checking global `fetch`. It exercises the list, upload, media, and delete calls. The test failed on the original source with “Illegal invocation” and passed after the change.

I audited source session bootstrap, the upload client, source media, and the shared AI proxy transport. Native Chromium reproduced the exact error on the old published upload client. Its standalone-call check also confirmed that the existing bare proxy `fetchImpl(...)` call works. The media path uses the corrected upload client. The audit found no second receiver defect.
