## Performance on the Pixel
Partial. No hardware measurements exist, and this session does not claim 60 fps. HDR keeps the existing quality budget; LDR caps DPR at 1.25 and reduces bloom to two post passes; safe mode caps DPR at 1 and allocates neither bloom nor shadows. These are fallback limits, not hardware benchmarks.

Validation: 32/32 Node rule/profile/content tests; 16/16 Tier A browser regressions; 22/22 exploration regressions; 14/14 A6 content/form browser checks; 19/19 startup checks at 524×1166 CSS px and DPR 2.06. Startup checks exercise real normal rendering, safe mode, each fallback level, failures in renderer/profiles/UI/controls/shadows/labels/first scene/first render, denied clipboard, and an actual null WebGL context. All browser rendering here uses software Chromium, not the Pixel GPU. The exploration regression finished at 24 draw calls, DPR 0.85 and 6 fps in software; that is not a Pixel measurement or a 60 fps pass. A safe-mode initial scene probe reported 20 draw calls. Page pauses the normal render loop while reading.

## Design choices worth comparing
Diagnostic bootstrap, Page and the 3D runtime are separate modules. Optional controls/labels can fail without killing the scene; a failed core scene/UI uses a readable form. Recovery keeps access ceilings rather than opening restricted content to make an error disappear. Content, reusable geometry templates, block selection and HTML presentation are separate modules. The Page-only URL imports no Three.js. Missing archival media remains an explicitly generated placeholder with readable fallback text. Trust never invents academic review from identity verification.
