## Proposed deployment boundary

One function, `ai-proxy`, in the **existing Living Atlas Supabase project**, plus the additive SQL attached. Static `index.html` remains on GitHub Pages; Three.js stays vendored. No schema work in Second Look and no new account/identity system.

The function uses the provider keys by secret **name** only. Supabase's platform-injected database connection stays server-side too; its availability will be verified by metadata/runtime behavior, never printing it. Parameterized SQL transactions through that connection keep reservations atomic without exposing an RPC or enabling a new public schema. If this platform binding is unavailable, stop and revise this proposal before adding a secret, role, connection service or schema exposure. No credential fallback through the browser.

After approval, the plugin read-only preflight selects Living Atlas by project name/ID, retrieves its URL and only its public anon/publishable key, inventories tables/functions, checks documented platform bindings, and inspects secret **names only**. Provider secret values are never fetched. Public client config can contain the verified project URL and public key; it contains no privileged key. An anon key identifies a project, not a person or agent permission.

### Request and origin contract

- Endpoints inside the single function: `OPTIONS`, `POST /session`, `POST /request`, and `POST /models` for metadata-only verification under the owner-issued benchmark grant. No visitor text in URL/query strings. Public Docent grants cannot call `/models`. Expiry cleanup runs during bounded bootstrap/admin maintenance; there is no extra public maintenance endpoint.
- Origin must equal the single value from `ALLOWED_ORIGINS` and the approved runtime config. Any unexpected secret/config value disables paid requests rather than broadening the list. CORS returns that exact origin, `Vary: Origin`, methods POST/OPTIONS, only required headers, and `Cache-Control: no-store` on token/model responses.
- Origins are checked before the body/provider work. CORS is **not authentication** and a raw HTTP client can spoof Origin. No reliance on the public anon key, Referer, test-owner mode, or a claimed profile ID for paid permissions. Other sites under the same GitHub Pages origin cannot be distinguished by Origin alone.
- Proposed gateway setting: `verify_jwt=false`, because these are explicitly anonymous, unbacked sessions, not Supabase Auth users. The function's own unpredictable bearer sessions, server grants, limits and global ceilings enforce access. No Auth configuration change is proposed.
- Body limit **48 KiB**, free visitor question **600 characters**, no conversation history. Session bodies have a smaller **2 KiB** bound. No arbitrary provider/model/endpoint, tool-call, SQL, system-prompt or schema-body fields are accepted from a visitor.
- `/request` envelope: `{requestId, job, agentId, schemaId, context:{placeId, catalogRevision, visibleBlockIds, lens, question}}`. Schema IDs and agents are server-registry entries. Model/challenger selection is available only within the owner-issued benchmark grant.
- Errors use fixed codes such as `RATE_LIMITED`, `LIVE_UNAVAILABLE`, `OUT_OF_SCOPE`, `STALE_CATALOG`, `BAD_PROPOSAL`; never echo request text, provider bodies or exception objects. A quota response includes bounded retry timing.

### Grants, session leases and concrete caps

`/session` mints 256-bit random bearer tokens. Database records hold SHA-256 digests, never the token strings. A persistent **anonymous browser holder** lasts 30 days; a tab session lasts 30 minutes. These are expiring quota handles with `backing_ref:null`, not verified people, accounts or Second Look identities. Tokens are never in URLs, logs, reports or Git. Clearing storage can acquire another anonymous holder; global limits remain the enforced boundary.

Public bootstrap issues only the pre-approved **look** grant for `guide / docent-silver / boycott / supported answer schema`. It cannot enable builder/background/heavy, private rooms, verified-only content, arbitrary agents or publication. The grant lasts at most one day and is individually revocable/receipted. Session renewal cannot reset holder/day or project counters. Other already-built simulated staff remain simulated.

The owner benchmark grant is minted through the approved administration path, not a client “Owner” switch: **suggest**, `builder / gus-benchmark / boycott`, the frozen kit schema plus narrowly allowed model-metadata checks, both verified candidate routes, maximum **40 paid attempts / $10 total / 24-hour expiry**, no scene writes. The bearer is supplied directly to the in-memory benchmark runner and never committed or printed.

All applicable limits must pass, including the smaller remaining budget; benchmark and public requests both consume the project/provider caps. Provider-dashboard limits are an extra boundary. Where a provider setting is only an alert or has delayed enforcement, do not call it a hard stop. Unknown pricing/account caps keep routes disabled. These dollar amounts are proposed approval limits, not claims about Nic's current billing settings.

**Atomic reservation:** a short database transaction locks the relevant session/grant/holder/project/provider buckets in a stable order, checks live leases, resolves the configured model and measured token envelope, increments call counters and reserves the **maximum billable amount** for the attempt. Commit the reservation before calling a provider; never hold a DB lock during network I/O. In-flight limits are counted from live call leases. The request dedupe key hashes only session ID plus client request UUID; the attempt/Receipt ID is a separate server UUID. Rolling-minute limits count admitted call leases from the preceding 60 seconds under the same session lock. Duplicate request IDs cannot issue a second charge; a pending duplicate returns pending, and a completed one returns completed without regenerating.

Provider-specific documented token counting or a verified conservative bound must cover the entire prompt/schema/template and maximum output, including billable reasoning/caching. Unknown bound or price means no paid call. Token caps in the proposed SQL are upper ceilings, not automatic permission to spend beyond the smaller budget. Provider-specific caching, tools and extra reasoning modes start off unless needed and bounded by the verified API contract.

On completion, a second transaction settles measured usage, releases only known unused reservation and writes exactly one call Receipt. If timeout/crash makes billing uncertain, retain the full reservation as spent until reconciliation; never blindly refund and retry. A stale call lease stops occupying a concurrency slot, but its monetary reservation is not released merely because time elapsed. Global budgets bound repeated anonymous registrations and spoofed-Origin requests.

Receipts are append-only in the service; database administrators remain trusted and can technically change records.

## One interface and automatic fallback

1. The existing `ai.request` boundary validates job/schema/context locally. Explicit local-only mode performs **no network request** and uses the simulated adapter.
2. Eligible live Docent calls request/reuse a server session and send only the narrow structured request. All other prototype staff stay simulated unless a separate valid server grant exists. Display a clear Agent / Live or Agent / Simulated badge, with actual model provenance.
3. The server independently selects blocks, validates scope/floors, reserves budget and calls the configured provider. It validates the proposed record before returning. Nothing edits Place content or acquires permissions.
4. Fetch failure, offline status, 401/403/429, provider refusal/error, invalid provider output, disabled/unverified route or a guide timeout automatically yields a **validated simulated result**. Show “Simulated · live helper unavailable” or “Simulated · live limit reached”; do not imply it came from the live model. Local-only mode and existing scripted questions remain available without an account.
5. Guide timeout: **20 seconds**; no automatic paid retries. A circuit breaker waits at least **60 seconds**, or Retry-After if longer, before another eligible live attempt. One request at a time; no background/frame-loop polling.
6. Changing room, Lens, grants or profile cancels/drops the stale result. It must not appear under a more permissive previous view. Client revalidates the returned proposal under the **current** rules before display/acceptance. Cancellation does not manufacture a fallback answer in a different room.
7. The response keeps `{proposal, model, agentId, receiptData}`. Source/provider, actual model, request Receipt ID and bounded fallback reason are metadata. No raw provider response/headers reach the UI. A rejected live attempt and a subsequent local simulated proposal are distinct recorded events.

Benchmark mode is stricter: outages or simulated fallback count as **unavailable**, never as a valid model answer. It does not quietly benchmark the simulator.
